1. Vocabulary Phrases
The following vocabulary applies in this document.
  1. "Thing" refers to a rule, definition or specification
  2. "Must" is an absolute requirement of a thing.
  3. "Must not" is an absolute prohibition.
  4. "Should" is a recommendation to implement a thing, although not doing so can be desirable in rare circumstances.
  5. "Should not" is a recommendation to not implement a thing, although doing so can be desirable in rare circumstances.
  6. "Optional" or "may" means a thing is discretionary. It is up to the implementation to decide to implement it or not.
  7. "Not restricted" is an option to implement a thing. It may be necessary for specific circumstances.
2. Mathematical Functions
Below are four mathematical analysis functions, and their behavior. Each mathematical and pseudocode definitions assume that lists are zero-indexed, meaning that list[0] accesses the first item of a list.
  • mean: This function must perform an average over a list of numbers. It is defined as:
    f(x) = (x0 + x1 + x2 + … + xi - 1) / i Where i is the number of items in the list. The equivalent pseudocode is: 
    mean(x):
if x is empty, return 0 or raise an error
let accumulator be 0
for each item in x, add value of item to accumulator
divide accumulator by the number of items in x
return accumulator
  • median: This function must find the median of a list. It is defined as:
    f(x) = {
    if i is even: (xi / 2 - 1 + xi / 2) / 2
    if i is odd: x(i - 1) / 2
    } i is the number of items in the list. The equivalent pseudocode is: 
    median(x):
let count be the number of items in x
if count is 0, return 0 or raise an error
if count is even, return (x[count / 2 - 1] + x[count / 2]) / 2
if count is odd, return x[(count - 1) / 2]
    Notes:
    • Both the mathematical and pseudocode definitions assume that the list is sorted by value.
    • The requirement of whether x must be sorted is up to the implementation. However, the choice carries heavy implications, because:
      • If x has to be sorted before calling the function, the implementation may produce a statistically "incorrect" output for an unsorted list. For an example, median([9, 1, 4]) returns 1 (incorrect) instead of 4 (correct).
      • If x is sorted in the function, there is a negligible performance overhead for when it attempts to sort an already sorted list. However, it produces the correct result regardless of whether x is or is not sorted.
    • The mathematical and pseudocode definitions use a zero-indexed system. This is specified at the top of Function Definitions, but this exists for clarity.
  • mode: This function must find the items in a list that occur the most.
    The pseudocode that defines its behavior is: 
    mode(x):
if x is empty, return an empty list or raise an error
let counts be a dictionary that uses keys to access values
let highestCount be 0
for each item in x:
	if item is not a key in counts, define item as 0 in counts
	let amountOfItem be the accessed item (a key) in counts
	increase amountOfItem from counts by 1
	if highestCount is less than amountOfItem, set highestCount to amountOfItem
if highestCount is 1, return an empty list
let commonValues be an empty list
for each entry of counts:
	if the value of entry is equal to highestCount, add the key of entry into commonValues
return commonValues
    Notes:
    • The implementation must return a list of items that occur the most.
    • If each item in x occurs only once, the implementation must return an empty list.
    • The pseudocode definition satisfies the rules above.
  • range: This function must find the distance between the largest and smallest numbers in a list. It is defined as:
    f(x) = max(x) - min(x) The equivalent pseudocode is: 
    range(x):
if x is empty, return 0 or raise an error
let minimumValue be the smallest value of x
let maximumValue be the largest value of x
return maximumValue - minimumValue
    Or more explicitly: 
    range(x):
if x is empty, return 0 or raise an error
let minimumValue be x[0]
let maximumValue be x[0]
for each item in x:
	if item is less than minimumValue, set minimumValue to item
	if item is greater than maximumValue, set maximumValue to item
return maximumValue - minimumValue
3. Global Edge Cases
The functions above assume that x is a list of items, and that each item is a numerical value. This chapter specifies functionality that may be included in each defined function. The functionality is as follows:
  1. If x is not a list of items, raise an error.
  2. If any item of x is not any numerical type, raise an error.
  3. If any item of x is a numerical type, but does not represent any specific value (ex. when an item is NaN), raise an error.
The above functionality prevents unexpected behavior. For an example, if mean was passed a string value, it can raise an error instead of returning an unexpected value.
4. Notes For Each Pseudocode Snippet
On an empty list, whether the functions must return 0 or an empty list, or throw an error is intentionally ambiguous. Therefore, it is up to the implementation to decide between either functionality for that case.
Importantly, how the functions are implemented is not a concern. What mainly matters is their functional correctness. For an example, an implementation of the mean function can use SIMD optimizations while retaining technical correctness.
5. Important Exceptions
Although this document assumes specific conventions that may or may not be possible:
  • If the implementation's environment uses a system that is not zero-indexed, the implementation is not restricted from adapting to this system. ex. MATLAB, R, Julia, Fortran, COBOL, and Lua, many of which are programming languages, use one-indexed systems.
